# Predictions for tools/ci/tests/test_inventory.py, eighth file (after review round 6), written by the assistant on
# 2026-11-20 before any of these cases first ran; no line changes after that run. The earlier files stay as they were.
#
# Why. Rounds 4, 5 and 6 each found Markdown that GitHub shows one way and the inventory read another way, and a reader
# that lists spellings is closed by the next spelling it does not list. So THEOREMS.md and kernel/coq/ANCHORS.md are
# now read in a named subset of Markdown (tools/ci/inventory.py, the function markdown), and anything outside it fails:
# (1) a carriage return not before a line feed (a CR LF line end is read as one, so the frozen decoy E03, THEOREMS.md
# in CR LF, holds still), U+FEFF, a control character (tab included), a character of Unicode category Cf, an
# ampersand, anywhere; (2) a heading's line (an ATX heading at any indent, every line of a setext heading's paragraph)
# and a table's header line hold only printable ASCII and U+2026, and none of "[", "<" and backslash; (3) the cells
# the inventory reads names from (the proved table's Statement, Statement file and Closing theorem cells, the
# Successors table's Old statement and Successor cells) hold nothing but commas and blanks outside backtick spans;
# (4) in THEOREMS.md every delimiter row lies under the header of the proved table, of a successor table, or of a
# table whose header holds only letters, digits, blanks, commas, U+2026 and the marks *, _ and ` (so the proved and
# successor rows read every other table's header as GitHub shows it; the frozen decoys E18 and E24, a plain table,
# hold still), and ANCHORS.md holds exactly one delimiter row; (5) "<!--" only on line 1, closed there, and "<"
# outside a code span only on line 1 and, in THEOREMS.md, on the lines "<details>", "</details>" and
# "<summary>...</summary>", each followed by a blank line (or "<details>" by its summary line); (6) a list item whose
# text starts with "#", and a line of "=" or "-" only under a list item's line. A heading at any indent counts as one
# (one inside a list item is indented).
#
# Where a refusal is printed. THEOREMS.md: the new row "THEOREMS.md: written in the Markdown subset this reader reads"
# (printed only when the file is read, as the row of block quotes), except that the heading rules (2 for a heading's
# line, and 6) fail the row "THEOREMS.md: every successor row names known statements", which reads every heading (so
# the frozen plant Q36, "## <em>Successors</em>", fails that row only, as predicted), and that rule (3) fails the row
# that reads the cell (the proved row, which then has no usable row for that folder, or the successor row).
# ANCHORS.md: every rule fails "ANCHORS.md: one row per gated folder with its variable" (the gate job's ANCHORS.md step
# calls the same reader).
#
# Plants: review 6's I01 to I08 with their controls (Q40 to Q52), m1, m2b, m2c, m3, m4, m5, m6 and a2b (Q53 to Q60),
# p1 to p6 with c1, c5 and c6 (Q61 to Q69); two decoys reviewers proposed that the subset refuses, frozen as refused (an
# ampersand in prose, Q70; a second one-line comment, Q71); and one plant for each further rule (Q72 to Q81). Decoys:
# E25 to E29. U02 and U03: the output paths (review 6's O1 and O1c). ZZ_ROW8 below is "| `zz32` | `zz32.ZZ_Statement.ZZ`
