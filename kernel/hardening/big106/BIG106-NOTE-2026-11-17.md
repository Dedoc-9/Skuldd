# The input +2^106 in the turns kernel: why the reduction's integer differs from x there, and only there

Written by the assistant on 2026-11-17, scratch. Grades: MEASURED (own) for the runs named; ARGUED for the derivation.

## What is proved and what is not

Proved (kernel-checked examples, `Big106.v` 65b0c923b3d082b5c18eb83bb4a08970700b64b208c53e27776996bff817cf4b, run
`runs/big1-console.txt` feb5e0fbffe6db6d8fe51075f05bc9dc7fe9fb2b07fbe7c787040065487385f8: 32 examples, each closed by
vm_compute, each with exactly the tier's four axioms, recursive coqchk exit 0 with every unsafe section empty), about
the frozen shapes of `mkf-ext/sincos32i` and `mkf-ext/sincos32z` at binary64:
- at +2^106: N = 2^106 - 2^53, f = 2^53, q = k = 2^55, r = +0; the sine before narrowing +0, the cosine 1; both
  functions and both stepped functions give +0 and 1;
- at -2^106: N = x and f = q = k = r = +0; the sine -0 (the input's sign), the cosine 1;
- at +2^104, +2^105, +2^107 and at the binary32 neighbours of +2^106 (0x747FFFFF, 0x74800001): N = x, r = +0.

Not proved: that +2^106 is the only binary32 input where N(x) differs from x. That is MEASURED over all 2^32 inputs by
the T2 sweep (`ext-work/sincos32-law/t2-sweep/sweep2-console.txt`, prediction P9 written before the run) and ARGUED
below. The law statement's clause (e) needs the lemma "for |x| >= 2^23 the remainder r is +0", whose proof must take
this input as its own case (f is 0 everywhere else, 2^53 here); that lemma is not written yet.

## Why (ARGUED)

The reduction computes N(x) = RN(RN(x + CN) - CN) with CN = 3 * 2^51, then f = x - N, q = 4f, k = N(q), r = q - k.
For |x| >= 2^23 (K_BIG) the selections discard all of these (the sine selects x * 0, the cosine 1), so no result
depends on them; clause (e) of the law still asks that each be finite, and in draft M that each be a zero or of
magnitude in [2^-400, 2^400). All of them are, here.

For a positive binary32 x with 2^e <= x < 2^(e+1):
- e <= 103: x + CN is exact (x is a multiple of 2^(e-23), CN of 2^51, and the sum fits 53 bits), so N = x.
- e = 104 and 105: x + CN rounds up to x + 2^53, and the subtraction rounds back to x (a tie to even at 104).
- e = 106: CN is under half an ulp of x (2^53), so x + CN rounds back to x; then x - CN is computed. If x is above the
  binade's bottom it stays in the binade and rounds back to x. If x = 2^106 exactly, x - CN falls into the binade
  below, whose ulp is 2^53, and CN is more than half of that ulp: the result rounds to 2^106 - 2^53.
- e >= 107: CN is under half the ulp of the binade below too, so even at a binade's bottom the result rounds back
  to x.
So N(x) differs from x only at x = 2^106. For a negative x the first operation moves toward zero; at -2^106 the first
rounding lands on -(2^106 - 2^53) and the second returns to -2^106 (the T2 sweep found no negative exception).
