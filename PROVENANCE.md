whole tree of Skuldd's first commit, the import. Each part has a manifest, `MANIFEST.<part>.txt`: one `sha256  path`
line per file, sorted by path. The manifests describe the import and are never rewritten; every change after it is
listed, file by file with its sha256 before and after, in `CHANGES-AFTER-IMPORT.md`.

How each part was taken:
- `orlog/` and `verdandi/`: every blob of the pinned commit's tree, written byte for byte as git stores it. The
  assembler recomputes each blob's git object id and refuses a mismatch, so no checkout's line-ending conversion can
  enter. Every file of both trees has mode 100644 (no executable, no symlink, no submodule), so taking blobs loses
  nothing. Their histories stay in the two original repositories.
- `kernel/coq/`: the tier's judged tree, byte for byte, without build products (`out4/`, `libcache/`, compiled
  objects). At assembly every freeze list was checked against the copy: 13 lists, 665
  entries, none missing and none with another sha256. The owner's own anchors for `sincos32i` (1477b814…e2d4) and
  `sincos32z` (a55d1c08…1172) are the sha256 of two of these lists.
- `kernel/hardening/` and `kernel/notes/`: named files and folders of the workspace (the law draft and its T2 sweep, `kernel/law/` and `kernel/evidence/`, are withheld: the import was assembled without `--with-law`), listed in
  `tools/assemble.py`, copied byte for byte.

To check a part: recompute the sha256 of each file and compare with its manifest line, then the manifest's own
sha256 with the table above.

## Re-pins after the import

A re-pin of `orlog/` or `verdandi/` is one dated note below, added by hand (not by `tools/assemble.py`) and never
rewritten. Its first line names the new pinned commit and its tree; the last note for a part names that part's pin.
The import table above and the four manifests stay as they are: they describe the import.
